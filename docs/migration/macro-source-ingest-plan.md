# 公开宏观源与 Tushare 采集方案

**待评审。** 为宏观、债券、黄金、美股择时及风格轮动补齐公开源和 Tushare 的存量采集与每日增量。债券四票的聚源和 Wind 数据仍走供应商同步链路。本方案覆盖数据接入，策略接线另行验证。

## 部署与写入

公司电脑运行 Wind、聚源、朝阳永续源表同步，沿用该 Dagster 实例的全局串行。Mac mini 运行公开源和 Tushare 日更，使用独立的 `DAGSTER_HOME`、SQLite 和队列。两台机器写同一 PostgreSQL 时按目标表明确唯一写入入口。将来若公司实例也运行需要并发的其他作业，再用共享 run 标签限制三家供应商合计一个 run，并保持单个同步作业内串行。公司电脑的 Task Scheduler 由负责人维护。见 [Dagster 本地运行存储](../adr/2026-11-17-dagster-local-run-storage.md)。

CLI 回填和 Dagster 日更调用同一个 `ingest` 作业，复用 PostgreSQL 适配器和 `src_<source>._batch`。回填显式指定区间并分批提交，日更从最近成功位置重查一段。作业按键和内容识别重复，原样重复跳过，已有键异值报错，有源版本身份的修订按新键追加。批次登记、数据写入与行数和 digest 回读在同一事务内完成，成功提交才推进水位。沿用双写闸与目标白名单，提交状态未知时停下核对。每源独立报告成功、无更新、预期数据未到或失败。公开源日更按自然日检查，具体时点以源端发布时间和执行机试跑为准。见 [采集层约束](../architecture/layers/ingest.md)。

| 数据源 | 存量 | 日更 |
|---|---|---|
| Tushare `shibor`、`us_tycr` | 按日期分段拉取，与 `wx2` 校对期限、精度和空值 | 重查近期区间，追加新日期，缺期单独报告 |
| FRED／ALFRED `DFII10`、`T10YIE`、`CPIAUCSL` | 按序列补齐研究期和预热期，核对可恢复的官方历史版本 | 按官方版本日期发现新增和对旧观测的修订 |
| 金十美国 ISM PMI | 对账历史接口与日历详情的交接期，保留统计期和源事件身份 | 发现新发布，复查近期事件的修订 |
| GPR `gprd_act` | 下载历史序列，核实可证实的文件版本 | 检查文件摘要，逐次登记可证实的版本及结构化数据 |
| WGC `WORLD/BARS` | 主报告归档匹配季度、发布日期和对应数值 | 检查主报告目录，按报告版本追加 |

## 评审事项与验收

- **源表结构**：建议 `src_tushare` 保留 API 原生宽表，期限长表在标准层转换。现有 DDL 是长表。FRED 现表同一序列和观测日只能留一值，建议新增窄旁表保存官方发布版本。金十现表缺 `period_end`，实施前核对目标列和统计期来源。沿用[按数据集增设版本旁表的裁定](../adr/2026-09-17-no-source-vintage-archive.md)。
- **PIT**：`as_of` 读取按来源发布证据和可执行契约选择版本，`_ingested_at` 只作采集记录。GPR、WGC 和金十历史版本缺证据时标明不可恢复范围。旧黄金 ISM 用 `< T`，旧美股用 `<= T`。按[新仓规则](../domain/pit-rules.md)实现严格截止，并以旧版冻结样本量化差异后裁定美股迁移口径。
- **实施与验收**：先用 SHIBOR 验证端到端，再接美债、FRED、金十、GPR 和 WGC。逐源核对覆盖、缺口和旧仓差异。同窗重跑新增零行，中断后从成功批次续跑，下一次真实发布自动追加并通过回读。最后在两台机器同时运行一次，验证队列独立和各目标表只有指定入口写入。
